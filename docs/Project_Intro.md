# PriceTrace | 영수증을 신뢰 가능한 가격 이력으로 바꾸는 앱

> PriceTrace는 실제 영수증의 구매 가격을 판매처·시점·상품 식별 정보와
> 함께 보존하고, 가격 비교와 공동 구매 정산으로 연결하는 로컬 우선
> 웹 애플리케이션입니다.

## 1. 30초 요약

- **문제**: 영수증에 남은 실제 구매 가격은 다시 비교하기 어렵고, 공동 구매 물품의 수량 배분과 입금 확인은 수작업에 의존합니다.
- **해결**: 영수증 품목을 출처와 시점이 있는 가격 관측값으로 구조화하고, 검색·비교·장바구니·정산 흐름으로 연결합니다.
- **핵심 결과**: 공개 샘플 95개 품목을 탐색하고, 수령자별 수량 배분·정산·백업/복원을 브라우저에서 처리할 수 있습니다.
- **기술적 차별점**: 상품명을 식별자로 사용하지 않고 판매처 상품 코드, 카탈로그 경계, 검토된 매핑을 기준으로 가격을 비교합니다.

## 2. 해결한 문제

| 사용자 문제 | PriceTrace의 해결 방식 | 가치 |
| --- | --- | --- |
| 실제 구매 가격을 다시 찾고 비교하기 어렵다 | 영수증 가격을 판매처·관측일과 함께 이력으로 저장 | 가격의 출처와 시점을 잃지 않음 |
| 이름이 비슷한 다른 규격 상품이 섞일 수 있다 | 상품 코드·카탈로그·검토 상태로 동일 상품을 판정 | 잘못된 가격 비교를 줄임 |
| 공동 구매 정산이 반복 작업이다 | 수령자별 수량 배분과 전달·입금 상태를 관리 | 초과 배분과 수동 합산 오류를 방지 |
| 잘못된 백업이 기존 상태를 손상할 수 있다 | 전체 파일을 Zod로 검증한 후에만 반영 | 기존 상태를 안전하게 보존 |

## 3. 핵심 사용자 흐름

```text
영수증 데이터 로드
  → 상품 검색·필터와 관측 가격 확인
  → 필요한 상품을 장바구니에 추가
  → 예상 구매 금액 확인
  → 공동 구매라면 수령자·수량 배분
  → 전달·입금 상태와 정산 메시지 관리
```

## 5. 담당 범위와 기여

- 제품 목표를 로컬 정산 MVP에서 검증 가능한 작은 사용자 흐름으로 분해했습니다.
- 원본 영수증, 가격 관측, 상품 카탈로그, 정산 상태의 책임과 진실 원천을 분리했습니다.
- Next.js UI, TypeScript 도메인 로직, repository/mapper 경계와 Zustand 상태를 구현했습니다.
- 외부 JSON과 백업 파일을 Zod로 검증하고, 실패 시 기존 상태를 보존하도록 설계했습니다.
- Supabase Auth·PostgreSQL·RLS·Edge Function으로 확장 가능한 원격 경계를 구성했습니다.
- lint, typecheck, Vitest, Playwright, GitHub Actions를 통한 검증·배포 경로를 만들었습니다.
- AI는 초안 생성과 반복 작업에 활용하되, 데이터 불변식·보안 경계·실행 결과는 코드와 테스트로 검증합니다.

## 6. 핵심 기술적 판단

### 상품명 대신 검증 가능한 상품 식별 경계를 사용

- **상황**: 판매처마다 표기가 다르고 같은 이름에도 용량·묶음·규격이 다른 상품이 존재합니다.
- **선택**: 판매처 상품 코드와 카탈로그 namespace를 보존하고, 검토된 표준 상품 매핑만 판매처 간 비교에 사용합니다.
- **이유**: 이름 유사도만으로 자동 병합하면 잘못된 최저가와 가격 추이를 만들 수 있습니다.
- **결과**: 자동화율보다 데이터 신뢰도를 우선하며, 불확실한 연결은 사람이 검토할 수 있는 상태로 남깁니다.

추가 의사결정과 트레이드오프는 [Project Detail](./Project_Detail.md)에 정리했습니다.

## 8. 현재 한계와 다음 단계

- 실제 사용자 인터뷰, 활성 사용자, 반복 사용률 같은 제품 성과 지표는 아직 확보하지 않았습니다.
- 가격 비교의 신뢰도를 높이려면 상품 규격과 판매자 관측 데이터가 더 필요합니다.
- 원격 동기화와 관리자 흐름은 실제 배포 환경에서 권한·장애·복구 시나리오를 재검증해야 합니다.
- OCR 자동 추출은 정확도와 사용자 검토 흐름이 확보되기 전까지 핵심 범위로 확장하지 않습니다.

**다음 한 단계**는 최신 UI에 맞춘 Playwright E2E와 production build를 실행하고,
그 결과를 CI와 문서에 연결하는 것입니다.
