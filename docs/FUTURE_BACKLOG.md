## 상품 바코드 (2026-10-27)

이번 범위는 로그인 없는 `get_public_product_by_barcode_v1(text)`와 EAN-13
체크섬, 검증된 ean/gtin 연결 조회, catalog ID 기준 중복 제거·충돌 반환,
기존 공개 정확한 규격·등재가 투영 재사용이다. 계약은
`docs/contracts/PUBLIC_BARCODE_LOOKUP_V1.md`에 고정한다.

시연 2건(더단백 40g, 테아닌과 밀크씨슬 60g)은 사용자의 실물 대조와
동일 상품 확인을 근거로 항목별 운영 SQL을 준비했다. 기존 연결이 다른
상품이거나 pending/rejected이면 덮어쓰지 않고 전체 등록을 중단한다.
원격 반영은 로컬 검증 후 별도 사용자 승인을 받아야 한다.

남은 범위:

- OCR `product_identity_candidates` 바코드를 verified 식별자로 올리는 관리자 승인 UI·RPC
- OCR 앱의 13자리 scheme 정규화, ML Kit 바코드 판독
- EAN-8 / UPC-A / GTIN-14 지원과 별도 체크섬·정규화 계약
- 검증된 근거와 항목별 승인을 갖춘 추가 바코드 연결

102개 상품 일괄 등록, 상품명으로 외부 바코드를 찾아 연결하는 방식은
이번 범위에 포함하지 않는다. 이름은 동일 상품의 증거가 아니다.

## 사용자 영수증 업로드 파이프라인

현재 로컬 `private-data/` 자동 인식 이후의 서버 기능이며 아직 구현하지
않는다.

1. 사용자별 접근 제어가 적용된 private object storage에 원본 이미지를
   변경 불가능한 증거로 저장한다.
2. 서버 작업 큐가 이미지를 읽고 `receipt.v2` 초안을 추출한다. 브라우저가
   OCR 공급자나 원본 storage에 직접 접근하지 않는다.
3. 원본 이미지 레코드와 추출 JSON 레코드를 별도로 저장하고, 추출
   버전·모델·프롬프트·처리 시각·원본 해시를 감사 정보로 남긴다.
4. JSON Schema 검증, 합계 대사, 중복 탐지, 비정상 가격과 낮은 신뢰도
   검사를 통과시킨다.
5. 자동 확정 기준에 못 미치는 영수증은 사용자 또는 관리자 검수 대기
   상태로 보낸다. 원본 JSON을 직접 수정하지 않고 새 수정 버전을 만든다.
6. 승인된 버전에서만 민감정보를 제외한 앱 표시용 projection을 생성하여
   페이지와 가격 관측 데이터에 공개한다.
7. 사용자 삭제 요청과 보존기간 정책은 원본 이미지, 추출본, projection,
   감사 로그별로 정의한다.
