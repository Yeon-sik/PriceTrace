## DEC002: 영수증 원본과 가격 관측을 서버에서 분리

- 날짜 : 2026-08-01

### feat/receipt-privacy-observation-design

#### 배경 / 제약

영수증에는 구매자 식별 단서, 거래 시각, 결제·거래 정보, 판매처의 상세 정보가
함께 포함될 수 있다. 영수증 ID와 항목 ID를 서버·공개 관측에 보존하면, 서버는
가격뿐 아니라 영수증 단위와 제출 관계를 알 수 있게 된다.

PriceTrace에는 공개된 판매처·지점 정보로 가격 출처를 설명할 필요가 있지만,
영수증 수나 제출자 수를 제품 기능으로 제공할 필요는 없다.

#### 선택지

1) 영수증 원본 또는 전체 OCR JSON을 서버에 저장하고 필요한 필드를 마스킹

2) 영수증 ID·항목 ID·거래 시각을 포함한 영수증 projection을 서버와 공개 데이터에 저장

3) 현재 적용안: 원본과 전체 OCR JSON은 로컬에만 보관하고, 서버에는 정규화된 판매처와
   날짜·상품/규격·단가로 구성된 가격 관측만 저장

#### 결정과 근거

3)을 선택한다.

서버의 도메인 객체를 영수증이 아니라 판매처별·날짜별 가격 관측으로 한정한다.
판매처 주소는 공개된 사업장 정보로서 정규화된 판매처 마스터에 보관할 수 있으나,
거래 시각·영수증 ID·항목 ID·제출자 ID는 가격 관측에 저장하지 않는다.

중복 방지는 로컬 영수증 ID, 짧은 요청 idempotency 키, 관측 의미 키의 병합으로
분리한다. 따라서 서버는 영수증 수나 동일 영수증의 제출 횟수를 저장·표시하지 않는다.
인증과 rate limit은 악용 방지를 위한 입구 책임으로만 두고, 저장된 관측과 연결하지 않는다.

#### 예외 처리

OCR 실패, 로컬 중복 의심, 사용자 지원, 대량 제출 대응은 원본 업로드의 예외가 아니다.
각각 로컬 수정·전송 보류·인증 입구 차단으로 처리한다.

원본 또는 제출자와 가격 관측의 연결이 필요한 새 예외는 별도 데이터 정책, 명시적 동의,
보유·삭제 기간, 접근 권한, 재식별 위험 검토를 먼저 결정한 뒤에만 검토한다. 기존 관측에
소급해 연결 정보를 붙이지 않는다.

#### 재검토 조건

- 법령 또는 사용자가 명시적으로 요구하는 증빙 보관 기능이 필요할 때
- 원본을 보지 않고는 해결할 수 없는 품질 검토 요구가 반복될 때
- 인증·rate limit만으로 데이터 조작을 통제하기 어려운 근거가 확인될 때

#### 결과 회고

구현 전 설계 결정이다. 구현 시 서버 DB, API, 로그, 오류 추적, 분석 이벤트까지
동일한 데이터 경계를 적용했는지 검증한다.
